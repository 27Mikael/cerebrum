## 6. Send client-minted ids to the daemon (note_id + bubble_id)

**What.** Now that the daemon accepts a client-supplied `note_id` (create note)
and `bubble_id` (create bubble), the client mints ids on create: **ULID** for
notes, **md5-of-name** for bubbles. The daemon uses `note_id` verbatim → the
server filename is `<noteId>.json`, so the on-device folder key and the server
filename **align** (no identity churn). The bubble id stays md5 (matching the
daemon fallback, and visually distinct from ULID note ids), so the client owns
identity end-to-end.

**Why.** Completes phase 4: create becomes a pure "first push of an already-local
thing" — the daemon no longer mints the identity the client then has to reconcile.

**Files.**
- `lib/api/bubbles_api.dart` — `createNote` takes optional `noteId` → adds
  `note_id` to the body; `createBubble` takes required `bubbleId` → sends it as
  the `bubble_id` query param.
- `lib/services/sync_service.dart` — `_push` passes the client `noteId` on
  create.
- `lib/services/id.dart` — added `bubbleIdFromName` (md5 hex, matches the daemon
  fallback) alongside `Ulid`.
- `lib/ui/screens/study_bubble/d_study_bubble_page.dart` — `createBubble` sends
  `bubbleIdFromName(name)`.
- `pubspec.yaml` — `crypto: ^3.0.6` promoted to a direct dependency (was
  transitive) for md5.

**Daemon note.** `create_study_bubble(..., bubble_id: str)` with no default is a
**required** query param in FastAPI, so its `if not bubble_id:` md5 fallback is
unreachable — use `bubble_id: str = ""` server-side if that fallback is wanted.
The client always sends one, so this is a heads-up, not a blocker.

**Verified.** `flutter analyze` clean. End-to-end create (folder key == server
filename) needs a device/daemon smoke test.

## 5. Follow-ups: note-delete outbox + auto-drain (poll-based reconnect)

**What.** Two gaps left after phases 1-4 are closed. (1) Deleting a note offline
now **propagates**: the delete is queued and replayed against the daemon on the
next drain, purging the local folder once the server confirms. (2) A
dependency-free **auto-drain** poll retries queued work every 20s while anything
is pending and stops itself once the outboxes clear — so a note saved offline
syncs on its own when the daemon comes back, without an OS connectivity plugin.

**Why.** Phase 2's delete only tombstoned locally (a note deleted offline would
never leave the server). And the only sync triggers were app start/resume, so a
reconnect *while the app stayed foregrounded* didn't retry. The poll is a
deliberate substitute for a connectivity listener: no new platform-channel
dependency, and it's free when idle because `drainOutbox` cancels the timer at
zero pending.

**Files.**
- `lib/services/sync_service.dart` — third outbox (`cerebrum_delete_outbox`): `queueDelete` (best-effort now, else queued; also drops any pending push for that note), `_drainDeletes`/`_pushDelete` (404 = already-gone → purge + dequeue; other errors stay queued), + delete outbox helpers. Added `_retryTimer`/`_ensureAutoDrain` (started from every `queue*`, cancelled by `drainOutbox` when `pendingCount()==0`). `drainOutbox` now drains notes → images → deletes. `pendingCount` sums all three.
- `lib/ui/screens/study_bubble/d_study_bubble_page.dart` — `deleteNote` tombstones locally then routes server-backed notes through `SyncService.queueDelete` (local-only notes are just purged); dropped its now-redundant try/catch.
- `lib/main.dart` — refreshed the resume-drain comment (auto-drain covers foreground reconnect now).

**Verified.** `flutter analyze` clean on both service/screen files. Offline
delete → reconnect propagation and the 20s auto-drain need a device/daemon smoke
test.

## 4. Phase 4 — client-owned identity + offline note create

**What.** Notes get a **client-minted ULID** the instant they're created, before
the daemon sees them, so a note can be created **fully offline**. The daemon's
`createNote` becomes "the first push of an already-local note" (materialise +
back-fill the server filename) rather than the thing that mints identity.

**Why.** `addNote` previously called `createNote` synchronously and threw when
offline — the last online-only hole in the flow. Client identity also gives every
note a stable key for the on-device folder independent of the daemon's filename.

**Files.**
- `lib/services/id.dart` — NEW `Ulid.generate()`: dependency-free 26-char
  Crockford base32 (48-bit ms timestamp + 80 bits randomness), time-sortable.
- `lib/ui/editor/editor_scaffold.dart` — mint note ids + image names via `Ulid`
  instead of `uuid` (dropped the `uuid` import).
- `lib/ui/screens/study_bubble/d_study_bubble_page.dart` — `addNote` rewritten:
  mint `note_id`, `NoteStore.writeNote` a blank note locally, `SyncService.queueSave`
  (first push, back-fills filename), open the editor — no synchronous server call.

**Decision.** Page ids stay `p{n}` (NOT ULID). The daemon synthesises `p1` and
keys per-page **analysis** reconciliation on those ids, so switching them risks
breaking analysis; the plan's page-id tidy was a parenthetical, and it needs a
coordinated daemon change to do safely.

**Verified.** `flutter analyze` clean. Offline-create → reconnect-sync needs a
device/daemon smoke test.

## 3. Phase 3 — offline images + stable `cerebrum-image://` refs

**What.** Inserting an image caches the bytes **locally first** (works offline)
and embeds a base-URL-agnostic ref `cerebrum-image://<noteId>/<name>` in the
document instead of an absolute daemon URL. The upload is queued and runs once
the note exists server-side. Rendering resolves the ref to a local file (else the
recorded daemon URL).

**Why.** Images were daemon-only: no offline render, upload failed offline, and
the stored **absolute URL broke whenever `baseUrl` changed** (daemon ↔ tunnel ↔
cloud). A ref fixes both.

**Files.**
- `lib/ui/editor/blocks/image/note_image_resolver.dart` — NEW. `resolve` (ref →
  local path / daemon URL, primed once per note via `configureForNote`), `toRef`
  (the inverse, for save), and `mapDocumentUrls`/`mapPagesUrls` walkers.
- `lib/services/note_store.dart` — image helpers: `writeImage`/`readImage`,
  `imagesDirPath`, `listImageNames`, `noteFilename`, and an `images/_manifest.json`
  sidecar (`setImageDaemonUrl`/`imageDaemonUrls`) recording each upload's URL.
- `lib/services/sync_service.dart` — image outbox (`cerebrum_image_outbox`):
  `queueImageUpload`, `_drainImages`/`_pushImage` (needs the note's server
  filename first, hence drained after note pushes).
- `lib/ui/editor/editor_scaffold.dart` — `imageUploader` now writes locally +
  queues + returns the local path; initState resolves refs → display srcs on
  load; `_save` maps display srcs → refs for the persisted/pushed copy.
- `lib/ui/screens/study_bubble/d_study_bubble_page.dart` — `configureForNote`
  (awaited) before opening the editor so refs resolve on the first frame.

**Design note.** AppFlowy 6.0.0's `ResizableImage` isn't exported and its image
component reads `node.attributes[url]` directly, so instead of a custom block
component the transform happens at the **boundaries**: the in-memory doc always
holds a loadable src (stock component + resize untouched), only persisted/pushed
copies hold the ref.

**Verified.** `flutter analyze` clean. Insert-offline → reopen (local render) →
reconnect (upload) needs a device smoke test.

## 2. Phase 2 — local-first reads

**What.** The notes screen shows the on-device copy **instantly** (offline
included), then background-refreshes from the daemon. Opening a note reads local
first and only prefers the daemon copy when online **and** the note has no
unsynced local edits.

**Why.** Reads were live-from-daemon — tunnel/cloud down meant nothing loaded,
and a background refresh could clobber a locally-dirty (queued) edit.

**Files.**
- `lib/ui/screens/study_bubble/d_study_bubble_page.dart` — `loadNotes` renders
  `NoteStore.listNotes` then merges the daemon list (keeping local-only/unsynced
  notes so a refresh can't drop them). `_openNote` reads `NoteStore.readNote`
  first; prefers the daemon copy only if online and not `dirty`; falls back to
  local on any network failure. Tiles tolerate local-only notes (keyed by
  `note_id` when there's no filename).

**Verified.** `flutter analyze` clean. Offline list/open needs a device smoke
test.

## 1. Phase 1 — writes never lost offline (NoteStore + SyncService rewire)

**What.** The core: an on-device JSON note store, writes go local-first (always
succeed), and the sync outbox is rewired to the live whole-page-set `/update`
contract. `SyncService.pushNote` (dead since the `/update` refactor) is gone.

**Why.** The client persisted notes **only on the daemon** — no local store, and
`SyncService`'s outbox was dead code, so offline = lost saves and no reads.

**Files.**
- `lib/services/note_store.dart` — NEW, the only filesystem toucher. On-device
  layout mirrors the daemon note-folder shape (per request): `notes/<noteId>/`
  with `manifest.json`, `.sync.json`, `images/`, and
  `pages/<pageId>/{content,ink,analysis,manifest}.json`, plus a `notes/_index.json`
  for the list. Content/ink are split per page because the scribble ink json is
  bulky; `analysis.json` is only stored when the daemon (which computes it) sends
  one. `writeNote`/`readNote`/`listNotes`/`markDeleted`/`purge`, image helpers,
  and `.sync.json` dirty/deleted/last-pushed state.
- `lib/services/sync_service.dart` — rewritten to the `/update` contract
  (`BubbleNotesApi.updateNote`; new notes create-then-update). Outbox in
  `shared_preferences`; on push success it persists the server-merged copy
  locally + clears dirty. (See change-sets 3 & 5 for the image/delete outboxes
  added on top.)
- `lib/ui/editor/editor_scaffold.dart` — `_save` writes to `NoteStore` first
  (marks dirty, mints a note id if missing), then best-effort `queueSave`.
- `lib/main.dart` — `drainOutbox()` on start; app now a `StatefulWidget` with a
  lifecycle observer that also drains on resume.
- `pubspec.yaml` — added `path_provider: ^2.1.5`.

**Verified.** `flutter analyze` clean (only the pre-existing
`editor_scaffold` `newDriver`/`curly_braces` lints and the unrelated
`responsive_layout.dart` error remain). `path_provider` needs a running platform,
so the filesystem round-trip needs a device smoke test.

## Follow-ups (not done)

- **Cross-device image display.** Documents now store `cerebrum-image://` refs
  (base-URL-agnostic, local-cache-first). A *different* device that lacks the
  local bytes can't resolve a ref — it needs the **daemon** to serve/resolve refs
  (or the note payload to carry a ref→URL map). Daemon-side; out of this repo.
- **Page ids stay `p{n}`.** Client-owned page ids (ULID) would need a coordinated
  daemon change so per-page analysis reconciliation doesn't break (see 4).
- **Stronger conflict handling** remains out of scope for v1 (LWW per page, as the
  `/update` diff already does).
