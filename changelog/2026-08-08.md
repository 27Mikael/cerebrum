## 2. Paged note editor (Xournal / Samsung-Notes style)

**What.** The editor is now a list of discrete **pages** instead of one endless
surface. Each page is a fixed-aspect A4 sheet with its own text (AppFlowy) + ink
(scribble) layers; pages are added explicitly (an "Add page" tile), and you can
switch between **vertical continuous scroll** (default) and a **horizontal
PageView slideshow** from a toolbar button.

**Why.** Handwriting + typing per page like a real notebook, and it maps 1:1 to
the daemon's `NoteStorage.pages` (each page = its own document + ink + version
vector), so sync/analysis/highlighting all work per page. Content does NOT
auto-flow between pages (that's word-processor pagination, which AppFlowy can't
do) — pages are discrete, exactly like Xournal/Samsung Notes.

**Files.**
- `lib/ui/editor/controllers/paged_note_controller.dart` — NEW `PagedNoteController`: manages a `List<NotePage>`, **reusing `NoteEditorController` unchanged as the per-page unit**; `fromNote()` (builds from `pages`, falls back to one page from legacy `content`/`ink`), `toPagesJson()`, add/remove page, `PageLayoutMode.vertical|horizontal`, global draw toggle.
- `lib/ui/editor/screens/page_surface.dart` — NEW `PageSurface`: one fixed-aspect (A4) sheet; `AbsorbPointer(editor)` + `IgnorePointer(ink)` stack (same draw-mode pattern as the old `EditorSurface`), bounded to the page. Ink is page-local because each page owns its scribble widget.
- `lib/ui/editor/screens/paged_editor.dart` — NEW `PagedEditor`: vertical `ListView` (default) / horizontal `PageView` over the shared `PageSurface`, + an "Add page" tile.
- `lib/ui/editor/editor_scaffold.dart` — swapped the single `NoteEditorController`+`EditorSurface` for `PagedNoteController`+`PagedEditor`; save/`_serializedEditorState` now serialise `toPagesJson()`; save payloads carry `pages` (+ a page-0 `content`/`ink` mirror for legacy readers); vim/switch-engine route through `activeController`; added the vertical↔horizontal layout-toggle button next to the draw toggle.

**Verified.** `dart analyze lib/ui/editor/` (nix flutter devshell) clean through
the core swap — the only issues reported are pre-existing (`newDriver` unused,
for-loop `curly_braces`, `vim_move_controller`), none in the new/changed paged
code. The layout-toggle button was added after that run and not separately
re-analysed — a final `dart analyze` + a device run are the remaining checks.

**Open.** Ink-coordinate normalisation (0..1) for pixel-identical strokes across
device widths (page-local bounded scribble is fine for a first cut); surfacing
sync `conflicted_pages` in the UI; page reorder/thumbnails.

## 1. Offline note sync (client half)

**What.** Note saves go through a version-vectored **push** to the daemon's
`/sync` endpoints; edits made while the daemon is unreachable are **queued in an
outbox** and retried on next launch. The server merges concurrent edits
(last-writer-wins per page, ink union) and hands back the merged note.

**Why.** Offline-first: you can keep editing with no daemon, and reconnecting
merges safely instead of clobbering. Matches the daemon's stream-C sync.

**Files.**
- `lib/api/sync_api.dart` — NEW: `push`/`pull`/`replicaId` → daemon `/sync/push|pull|replica-id` (same `ApiConfig.headers()` convention as the other api classes).
- `lib/services/sync_service.dart` — NEW `SyncService`: a stable device **replica id**, a per-note **version vector**, and an offline **outbox** (all in `shared_preferences`, the app's only local store); `pushNote` bumps our vector slot → stamps `metadata.version_vector` → enqueues → pushes → adopts the server's merged vector; `drainOutbox` retries queued pushes.
- `lib/main.dart` — `SyncService.drainOutbox()` on startup (fire-and-forget) after `ApiConfig.init()`.
- `lib/ui/editor/editor_scaffold.dart` — existing-note saves route through `SyncService.pushNote` (see change-set 2 for the paged payload).

**Verified.** `dart analyze` clean (no issues in the new files). Live run
pending (queue-offline → reconnect-merge behaviour needs a running daemon).

**Note.** No client-side note DB yet (only `shared_preferences`), so this gives
resilient conflict-safe *pushes*, not full offline note *reading* — that needs a
local note store (a follow-up).
