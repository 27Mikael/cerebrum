## 2. Connection settings panel + secure daemon key

**What.** A "Connection" settings page: local/cloud mode toggle, a base-URL
field per mode, and a daemon-key field. Moved the daemon key into secure
storage.

**Why.** Two gaps left after change-set 1: nothing ever *wrote* the local-mode
`daemon_api_key` the request headers read (so local mode couldn't authenticate),
and there was no way to set the cloud (Leapcell) URL or flip modes from the UI.

**Files.**
- `lib/ui/screens/settings/connection_settings.dart` — NEW: loads current mode + per-mode URLs + daemon key; `SegmentedButton` mode toggle; URL fields; obscured daemon-key field; Save persists via `ApiConfig` + `UserSession` with a confirmation snackbar.
- `lib/ui/screens/settings/settings.dart` — wired page 2 to `ConnectionSettings`; relabelled the sidebar entry "System" → "Connection".
- `lib/services/user_session.dart` — `saveDaemonKey`/`getDaemonKey` backed by `flutter_secure_storage` (the key is a secret and was previously never stored); per-device, so it survives logout and is cleared only by `resetAll`.
- `lib/api/api_config.dart` — reads the daemon key from secure storage instead of the never-written SharedPreferences value; added `urlFor(mode)` so settings can display stored URLs.

**Verified.** `dart analyze` on the four files (via the flutter nix devshell) — no issues.

## 1. Wire client to the daemon's credential auth (bearer token, login/signup)

**What.** Replaced the passwordless create-account flow with real signup + login
against the daemon: `POST /user/login` returns a bearer token that's stored
securely and sent on every request. Fixed the account routes that changed
server-side.

**Why.** The daemon now requires a unique email + bcrypt password and issues a
per-user bearer token (mandatory in cloud mode; identity is no longer a trusted
`X-User-Id` header). The client sent no password and no token, so signup 422'd
and cloud requests would 401. Account get/delete also moved to identity-derived
routes (no path id).

**Files.**
- `lib/api/api_config.dart` — attaches `Authorization: Bearer <token>` (alongside `X-Daemon-Key`/`X-User-Id`); added a `DeploymentMode.local|cloud` switch with per-mode base URLs, hydrated by `init()`.
- `lib/main.dart` — `WidgetsFlutterBinding.ensureInitialized()` + `await ApiConfig.init()` before `runApp`.
- `lib/services/user_session.dart` — token stored in `flutter_secure_storage`; `saveSession`/`getToken` (renamed from `saveUser`); `isLoggedIn()` now checks for a token; `clear`/`resetAll` wipe it.
- `lib/api/user_api.dart` — NEW `login()` + `signUp()`; `createAccount` requires email + password; `deleteAccount()`/`fetchCurrentUser()` hit `/user/account` (no path id); NEW `InvalidCredentialsException`.
- `lib/ui/screens/onboarding/login_screen.dart` — added a password field and a signup/login toggle wired to `UserApi.signUp`/`login`.
- `lib/ui/app_entry.dart` — refreshed the stale comment on `onLoggedIn`.

**Verified.** `dart analyze lib/` — the six changed files report no issues (the 20 pre-existing issues are all in untouched files).
