Theme for the day: making the paged editor feel **continuous** — text reflows
across pages live while you type (caret intact), tables split cleanly across a
page break, and the drawing dial becomes a single screen-level control that
follows you across pages.

## 4. Single screen-level drawing dial (placement + active-page tracking + tool-follow)

**What.** The radial tool dial is now **one** control mounted on the editor
screen, not one embedded in every page. It's shown only in drawing mode, floats
above the whole page list, and drives the **active** page. Touching a page makes
it active, and a picked pen/highlighter/eraser **follows across pages**; undo/redo
stay page-local.

**Why.** A dial per page duplicated the button on every sheet and clipped the
wheel to a single page's bounds. Centralising it needs two things to actually
work: (1) the active page must track where you're interacting — `setActive` was
only ever called by the horizontal `PageView`, so in vertical scroll the dial
would have hit page 0 regardless; (2) a single dial with per-page pens is
incoherent, so the tool selection has to follow you.

**Files.**
- `lib/ui/editor/screens/drawing_layer.dart` — removed the per-page `ToolDialHub`; `NoteDrawingLayer` is now just the page's Scribble canvas.
- `lib/ui/editor/editor_scaffold.dart` — mounted one `ToolDialHub` in the body `Stack` (drawing-mode gated, driven by `activeController.drawingNotifier`, `onSelectTool: applyDrawingTool`). `Positioned.fill` wraps the `AnimatedBuilder` so parent-data stays valid; empty overlay areas don't absorb pointers, so strokes still reach the canvas.
- `lib/ui/editor/screens/paged_editor.dart` — per-page passive `Listener(onPointerDown → setActive(i))` so the touched page becomes active without disturbing draw/text gestures.
- `lib/ui/editor/controllers/paged_note_controller.dart` — `setActive` guards redundant same-index notifies; new `_activeTool` + `applyDrawingTool` (remembers the tool and **broadcasts** it to every page's notifier — no pointer-dispatch ordering race); `_initPage` applies `_activeTool` so new/reflow-rebuilt pages inherit it. Added `package:scribble` import.
- `lib/ui/editor/screens/radial_tool_dial.dart` — `onSelectTool` callback + `_selectTool` (persistent tools route through it; undo/redo stay on the active notifier); refreshed the stale "lives per page inside a ListView" comment.

**Verified.** `dart analyze` clean on all touched files (only the pre-existing
`editor_scaffold` `newDriver`/`curly_braces` lints remain). Device run to confirm
the single dial + follow behaviour is the remaining check.

## 3. Table splitting across page boundaries

**What.** A table taller than the remaining space now **splits by row** across
the page break instead of taking its own (possibly overflowing) sheet. Head keeps
the first rows; the tail's cell `rowPosition`s are reindexed to 0-based so it's a
standalone valid table.

**Why.** Tables were kept atomic after an earlier attempt "vanished" them.
AppFlowy's `TableNode` silently renders nothing unless `children.length ==
colsLen * rowsLen`, every cell has `rowPosition`/`colPosition`, and every grid
coordinate is covered — the first splitter violated that. Column widths / row
heights are stored **per cell**, so they travel with the cell; only `colsHeight`
(a cached total) needed dropping.

**Files.**
- `lib/ui/editor/controllers/page_paginator.dart` — `_isSplittable` now includes tables (`_tableIsSplittable`, rows > 1); `_splitTable` rewritten to emit two valid tables (reindex tail rows, preserve `colsLen`/`colPosition`/per-cell dims, drop cached `colsHeight`) with an explicit `colsLen × rows` invariant guard that keeps ragged/merged-cell tables atomic rather than emit something AppFlowy would drop.
- `test/table_split_test.dart` — NEW: reconstructs every emitted half through the **real** `TableNode` and asserts it's accepted; conservation as a multiset; single-row stays atomic; repeated splits across many pages.

**Verified.** `flutter test test/table_split_test.dart` — 4 tests green (validity,
cell conservation, single-row-atomic, repeated split). `dart analyze` clean.

## 2. Reflow after a page merge (no scrollable sheets)

**What.** `mergePageIntoPrevious` now runs `repaginate()` after merging.

**Why.** A merge concatenated the pulled-up content onto the previous page
without respecting the line budget, so a leading table backspaced up left that
fixed-height A4 sheet overflowing — and because the embedded editor is
`shrinkWrap: true`, the overflow turned the page **scrollable**. Reflow pushes the
excess onto following pages (with table splitting from change-set 3, a too-tall
table now splits across the break); no-ops when it already fits, and preserves the
caret seeded at the seam.

**Files.**
- `lib/ui/editor/controllers/paged_note_controller.dart` — `repaginate()` call at the end of `mergePageIntoPrevious`.

**Verified.** Pure-Dart check: a 46-line merged page reflows to a 39-line text
page + the table on its own page; no non-table page overflows. `dart analyze`
clean.

## 1. Live continuous pagination + caret hand-off

**What.** Reflow now fires **live while typing** (debounced), not just on the
Reflow button, and the **caret is preserved** across the rebuild — so text spills
onto the next page as you type and the cursor stays where you were.

**Why.** The paginator existed but was manual and lost the caret on rebuild. Live
reflow needs to (a) not thrash on every keystroke and (b) re-land the caret even
when a block was split.

**Files.**
- `lib/ui/editor/controllers/paged_note_controller.dart` — debounced trigger (`_scheduleReflow`/`_reflowTimer`, 450ms) wired on every page via `_initPage`, guarded by `_suppressReflow` against rebuild reentrancy; `repaginate` rewritten to snapshot the caret as a **global character offset** over the flattened block stream (`_captureGlobalCaret`/`_locateCaret`/`_CaretTarget`) — an anchor that survives splitting because the paginator conserves that text exactly — and to do a **targeted rebuild** that reuses the unchanged prefix of pages (their live editor state survives).
- `lib/ui/editor/controllers/appflowy_text_driver.dart` — `initialCaretOffset` (arbitrary offset seeding, clamped to the block) + a `caret` getter for the snapshot.
- `lib/ui/editor/controllers/page_paginator.dart` — exposed `blockPlainText` for the global-offset measurement.
- `lib/ui/editor/editor_scaffold.dart` — refreshed the Reflow-button comment (now a manual escape hatch alongside the live trigger).

**Verified.** Pure-Dart checks against the real paginator: text conserved through
reflow; caret global-offset round-trips exactly; `paginate` is **idempotent** (so
the live trigger can't loop). `dart analyze` clean on the touched controller files.

**Open.** Live reflow rebuilds controllers when a page overflows — a debounce
lands it in a typing pause, but a heavier in-place (transaction-based) reflow would
avoid the rebuild entirely; row-granular table splitting can still overflow on a
single row taller than a whole sheet.
