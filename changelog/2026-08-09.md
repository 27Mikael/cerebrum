## 5. Durable block ids so tap-a-block analysis survives edits/reorders

**What.** Every editor block now carries a **stable id** that round-trips through
save/load, and the inline per-block analysis popover is keyed by that id instead
of the block's position. Tapping a block still shows its findings after blocks
above it are added, removed, or reordered.

**Why.** AppFlowy 6.0.0's `Node.toJson()` **omits** the node id and
`Node.fromJson()` **ignores** it, so every load minted fresh `nanoid`s — block
identity was effectively ephemeral. The daemon therefore fell back to positional
`blk{i}` ids, which the app parsed back into indices. Any insert/reorder (or a
concurrent page-blob sync) invalidated that mapping, so the popover lit up the
wrong block. Fixing it needs a genuine round-trip: emit the id on save AND restore
it on load — mirroring how ink strokes already carry a stable stroke id.

**Files.**
- `lib/ui/editor/controllers/appflowy_text_driver.dart`
  - `documentJson` — serialises each node **with its `id`** (`_nodeToJsonWithId`, recursive; same `type`/`data`/`children` shape as before, plus `id` at every level).
  - `_constructEditorState` — after `Document.fromJson` mints fresh ids, `_restoreNodeIds` walks the raw JSON and the parsed node tree in parallel and copies each persisted `id` back onto its node (`Node.id` is mutable). Closes the round-trip so a block keeps one id across reloads.
  - added `selectedBlockId` (the stable id at the caret); `selectedBlockIndex` is now used only for on-screen positioning (`rectOfBlock`).
- `lib/ui/editor/editor_scaffold.dart` — `_blockAnalysis` is now `pageId → blockId → chunks` (keyed by stable id). `_flattenAndSortChunks` keeps `source_block_ids` as string `blockIds` (dropped the `_blkIndex` numeric parse); `_rebuildBlockAnalysis` / `_lookupBlockAnalysis(pageId, blockId)` follow.
- `lib/ui/editor/screens/paged_editor.dart` — `BlockAnalysisLookup` second param is now `String blockId`, not `int blockIndex`.
- `lib/ui/editor/screens/page_surface.dart` — `_resolveActive` looks up chunks by `selectedBlockId`, keeping the block index only to draw the highlight rect.

**Migration.** Existing notes have no persisted ids on first open → the editor
mints ids → the first save persists them → durable thereafter. During that window
(and for id-less/imported content) the daemon's content-hash fallback keeps the
mapping stable rather than index-fragile.

**Verified.** Manual review + grep: no stale `blockIndices`/`_blkIndex`/`int
blockIndex` refs remain in the analysis path; new symbols wired end-to-end.
`flutter analyze` still to be run in the nix devshell (no Dart toolchain outside
it here); device run to confirm the popover tracks the tapped block after a
reorder is the remaining check.

## 4. Single screen-level drawing dial (placement + active-page tracking + tool-follow)

**What.** The radial tool dial is now **one** control mounted on the editor
screen, not one embedded in every page. It's shown only in drawing mode, floats
above the whole page list, and drives the **active** page. Touching a page makes
it active, and a picked pen/highlighter/eraser **follows across pages**; undo/redo
stay page-local.

**Why.** A dial per page duplicated the button on every sheet and clipped the
wheel to a single page's bounds. Centralising it needs two things to actually
work: (1) the active page must track where you're interacting — `setActive` was
only ever called by the horizontal `PageView`, so in vertical scroll the dial
would have hit page 0 regardless; (2) a single dial with per-page pens is
incoherent, so the tool selection has to follow you.

**Files.**
- `lib/ui/editor/screens/drawing_layer.dart` — removed the per-page `ToolDialHub`; `NoteDrawingLayer` is now just the page's Scribble canvas.
- `lib/ui/editor/editor_scaffold.dart` — mounted one `ToolDialHub` in the body `Stack` (drawing-mode gated, driven by `activeController.drawingNotifier`, `onSelectTool: applyDrawingTool`). `Positioned.fill` wraps the `AnimatedBuilder` so parent-data stays valid; empty overlay areas don't absorb pointers, so strokes still reach the canvas.
- `lib/ui/editor/screens/paged_editor.dart` — per-page passive `Listener(onPointerDown → setActive(i))` so the touched page becomes active without disturbing draw/text gestures.
- `lib/ui/editor/controllers/paged_note_controller.dart` — `setActive` guards redundant same-index notifies; new `_activeTool` + `applyDrawingTool` (remembers the tool and **broadcasts** it to every page's notifier — no pointer-dispatch ordering race); `_initPage` applies `_activeTool` so new/reflow-rebuilt pages inherit it. Added `package:scribble` import.
- `lib/ui/editor/screens/radial_tool_dial.dart` — `onSelectTool` callback + `_selectTool` (persistent tools route through it; undo/redo stay on the active notifier); refreshed the stale "lives per page inside a ListView" comment.

**Verified.** `dart analyze` clean on all touched files (only the pre-existing
`editor_scaffold` `newDriver`/`curly_braces` lints remain). Device run to confirm
the single dial + follow behaviour is the remaining check.

## 3. Paged model: discrete pages + forward-only overflow (replaces continuous pagination)

**What.** The editor settled on a **discrete-page** model. Pages don't reflow;
when a page fills, its overflowing tail moves **whole-block** onto the next page
(created if needed) and the caret follows. Backspace at a page's start still
merges up. Tables move whole — never split.

**Why.** Continuous pagination (built earlier today: live reflow on every edit +
caret hand-off + row-level table splitting) reflowed by tearing down and
rebuilding page controllers. That **churned page ids** (the sparse
`p0/p9/p10/p11` folders seen on disk), **jumped the caret** at page boundaries (a
flat char-offset anchor couldn't tell "start of block N" from "end of block
N-1"), and fought the daemon's stable-`page_id` model (per-page versioning /
analysis / sync). Discrete pages remove the churn while still giving forward flow
+ backspace-merge.

**Files.**
- `lib/ui/editor/controllers/paged_note_controller.dart` — removed the continuous-pagination engine (`repaginate`, `_scheduleReflow`/`_reflowTimer`, `_captureGlobalCaret`/`_locateCaret`/`_CaretTarget`, `_samePageBlocks`, `_maxPageIdNum`, the post-merge reflow). Added **`pushOverflow`** (forward-only: move blocks `[from..]` onto the next page, caret follows, `_flowing` guard) + `_nextPageId`. `mergePageIntoPrevious` is now a plain discrete merge.
- `lib/ui/editor/screens/page_surface.dart` — overflow detector: after layout, measures each block's rendered bottom vs the sheet and reports the first overflowing block via `onOverflow` (keeps ≥1 block per page).
- `lib/ui/editor/screens/paged_editor.dart` — `onOverflow: (from) => c.pushOverflow(i, from)` wiring.
- `lib/ui/editor/editor_scaffold.dart` — removed the "Reflow" button.
- **Deleted** `lib/ui/editor/controllers/page_paginator.dart` and `test/table_split_test.dart` (the continuous paginator + its table-split test).

**Note.** An oversized **table** (taller than a whole sheet) overflows its own
page — whole blocks only, nothing splits. `TODO(tables)` in `pushOverflow` (the
verified row-splitter lives in git history).

**Verified.** `dart analyze lib/ui/editor/` clean. Overflow is measurement-based
→ **needs a device smoke test**.

## 2. Image uploads stored in each note's own folder

**What.** A **"/image"** slash item → pick a file → upload → drop an AppFlowy
image block. Bytes are stored on the daemon in the note's own folder:
`notes/<note_id>/images/<ulid>.<ext>`.

**Files.**
- `lib/api/bubbles_api.dart` — `uploadNoteImage(...)` (multipart POST with auth headers → absolute URL).
- `lib/ui/editor/controllers/appflowy_text_driver.dart` — `_imageMenuItem` + `_pickUploadInsertImage` (file_picker `withData` → `imageUploader` → `imageNode`), plus the `imageUploader` hook.
- `lib/ui/editor/controllers/paged_note_controller.dart` — `imageUploader` setter, pushed onto every page's driver (incl. pages created later) via `_initPage`.
- `lib/ui/editor/editor_scaffold.dart` — wires the uploader (reads `filename` dynamically so it works once a new note is first saved; "Save the note before adding images" guard). Daemon endpoints: see the daemon changelog.

**Note.** Image GET is auth-exempt (capability URL) and the node stores an
**absolute** URL (breaks if `baseUrl` changes). Both are called out for the
offline-first pass (local image cache + stable refs).

**Verified.** `dart analyze` clean; **needs a device smoke test** (picker +
upload + render).

## 1. Fix: note saves dropped their `bubble_id` (404 loop)

**What.** The editor captures `bubble_id` **once** at open into a stable field
and uses it for every request; save bails quietly when it's empty; the
update-response merge no longer clobbers it.

**Why.** The daemon echoed an **empty** `bubble_id` (a computed field off
`manifest.bubble_id`, which was never persisted), and `_save`'s
`note.addAll(response)` overwrote the good value → the next autosave built `PUT
/bubbles//notes/update/...` → **404 every 2s**. (Daemon-side persistence fix: see
the daemon changelog.)

**Files.** `lib/ui/editor/editor_scaffold.dart` — `_bubbleId` captured in
`initState`; `_save` guard; response no longer clobbers it; the three analysis
calls use it too.

**Verified.** `dart analyze` clean.
